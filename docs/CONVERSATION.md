## 四、关键决策

| 决策 | 结论 | 原因 |
|-|-|-|
| 技术栈 | 原生 HTML/CSS/JS，无框架 | 文件少、可直接静态托管、迁移成本低 |
| 版式 | 文档站而非博客 | 阅读与检索效率优先，符合知识库定位 |
| 视觉 | 浅灰底 + 白色内容面 + 青色强调 + 等宽标签 | 与工程文档气质匹配 |
| 站点命名 | 现场笔记 · 机器人运维 | 突出个人一线经验与运维定位 |
| 地址策略 | 平台地址不变，外挂短链 301 | 平台不支持自定义域名 |
| 仓库策略 | 公开仓库 + 文档 + Pages 镜像 | 免费账号下私有仓库无法启用 Pages |
| 发布通道 | Pages 采用分支发布（main / 根目录） | Actions 制品方式部署失败，分支发布更稳定 |
| 文档基线 | CentOS 7.8，RCS 3.x/4.x，硬件以潜伏叉车为主 | 与现场实际部署环境一致；不同厂商中间件与控制器存在差异 |
| 厂商内容归属 | 厂商手册整理笔记按主题并入主库分类，不设独立「速览」区 | 用户要求打散归档；避免来源割裂，首页检索可一次性覆盖全部 26 篇 |

## 五、短链方案要点

- 首选 Cloudflare Worker：`go.<domain>` 全路径 301 到平台地址，支持子路径透传。
- 备选 DNS 显性 URL 转发：零维护，但需确认服务商是否支持子路径，且国内需备案。
- 不选第三方短链平台：多为 302、依赖他人服务、无法长期掌控。
- 验证口径：`curl -I` 返回 301、`location` 正确、深层链接仍可访问。
